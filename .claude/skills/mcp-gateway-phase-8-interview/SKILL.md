# Phase 8 · 面试收尾

## 目标

1. 一份讲得清的 README：架构、核心机制、决策记录。
2. 30 秒项目介绍话术（背熟）。
3. 高频追问清单与你的答案（自己能复述，不背稿）。

## 前置条件

- [ ] Phase 0–7 全部完成，决策日志完整（`docs/decision-log.md` 有每个阶段的决策）。

## 任务步骤

### Step 1 README.md

包含：

- **定位**：一句话——"MCP 网关：对 AI 客户端是 MCP Server，对下游业务系统是 MCP Client，统一承担命名空间路由、鉴权、熔断、限流、可观测"。
- **架构图**：ASCII 或 Mermaid（复用能力清单的 flowchart：客户端 → 网关 → 下游/自有工具）。
- **核心机制**（每节 3–5 行）：命名空间透传、元工具、熔断降级、双链路鉴权、流控、存储。
- **快速开始**：mock 下游 + 网关启动 + curl 三连。
- **目录结构**：包 → 职责 映射。

### Step 2 决策记录整理（面试弹药）

把 `docs/decision-log.md` 提炼成"为什么这样做"清单，每条能讲 1 分钟：

| 决策 | 一句话理由 | 备选方案 |
| --- | --- | --- |
| `{alias}__{toolName}` 双下划线命名 | 客户端 tool 名字符集限制 `[a-zA-Z0-9_-]`，点号/斜杠会被拒 | 点号、斜杠、JSON 包一层 |
| 网关不透传上游凭证 | 避免外部 token 格式传染给每个业务 server；下游信任网关已鉴权 | 透传原 token |
| 重试只覆盖连接失败 | MCP tool 多带副作用，网关无法判断幂等性，盲重试有重复执行风险 | 全量重试、幂等键 |
| DOWN 时工具从列表移除 | AI 客户端看到 tool 存在就会反复尝试，藏起来让它更快改走其他路径 | 保留并报错 |
| list_tools 不带完整 schema | 下游 tool 多了全量 schema 吃下游窗口 | 全量返回 |
| 白名单才透传 | 下游发版新增的 tool 不应无声无息成为对外能力 | 全量透传 |
| Spring AI 运行时增删 tool 结论 | （填 Phase 0 实测结论） | 启动时同步 |

### Step 3 30 秒讲稿

模板（按你自己的话改）：

> "我做了个 MCP 网关，基于 Spring AI 2.0。它解决的核心问题是：AI 客户端要调用公司十几个业务服务，如果每个服务都单独对接，客户端要维护一堆连接。网关让客户端只连一个端点，对客户端它是 MCP Server，对下游它是 MCP Client，下游对客户端透明。我做的东西里，最难的有三块：一是命名空间路由——所有下游工具统一成 `alias__tool` 的名字，包括白名单、schema 改写、冲突 fail-fast；二是熔断降级——单个下游挂掉不能拖垮整个网关，DOWN 时把它的工具从客户端列表里藏起来；三是双链路鉴权——内外网两套部署共用一份代码，靠 CallerContext 统一身份。另外还做了限流、指标、审计落库。"

### Step 4 高频追问清单（自己先答一遍）

1. 为什么网关要同时是 MCP Server 和 MCP Client？两个角色各自的职责边界？
2. 如果 Spring AI 不支持运行时增删工具，你的透传刷新怎么退化的？
3. 熔断阈值 50%/5 次是怎么定的？半开为什么是 30 秒？
4. 下游返回 1MB 响应怎么处理？为什么截断而不是拒绝？
5. 限流为什么只对 tools/call 计量？
6. 多实例部署时，熔断状态和 Key 缓存在实例间怎么一致？（诚实回答当前取舍 + 演进方向）
7. `gw__invoke` 为什么是逃生通道而不是主路径？
8. 审计为什么只记字段名和长度，不记 arguments？
9. 如果让你加"下游动态注册（服务发现）"，你会怎么设计？
10. 网关是安全边界上的单点，怎么缓解？（凭证管理、审计、熔断、限流）

## 验收标准

- [ ] README 完整，能独立看懂并启动。
- [ ] 30 秒讲稿能脱稿讲，无卡顿。
- [ ] 10 个追问每题有自己组织的答案（写下来或能口头讲）。

## 常见坑

- **只讲做了什么，不讲为什么**：面试官要的是决策依据，不是功能清单。
- **背稿**：追问一变形就答不上来；用"决策记录"组织，按原理回答。
- **贬低取舍**：诚实说"初版没做动态注册，因为配置能支撑十几个下游"，比硬吹强。

### 面试亮点
- **为什么用 Spring AI 2.0？** 最新版本，原生支持 MCP 协议，不用自己写协议层
- **为什么手写熔断不用 Resilience4j？** 手写能讲清状态机原理，面试加分
- **为什么同步写审计？** 初版简单，后续可换队列异步——诚实说取舍比硬吹强
- **为什么用双下划线命名？** MCP 命名规范限制，按第一个 `__` 切分

### 项目整体架构
```
客户端 → ApiKeyFilter → RateLimiter → CircuitBreaker → ToolRegistry → 下游
         ↓              ↓             ↓              ↓
       CallerContext   令牌桶       三档状态机     ConcurrentHashMap
         ↓              ↓             ↓              ↓
       ThreadLocal     tenantId     UP/DEGRADED/DOWN  alias__tool
```
